Measurement guide

Understand the readings

How recording works

The collector asks macOS for battery and activity readings every 60 seconds by default. It saves them in a SQLite database, a file on your Mac, so you can look back later.

It reads numbers and app names. It does not record your screen, keystrokes, browser history, or document contents.

Battery level

The charge remaining, as a percentage reported by macOS. “Plugged in” means a power adapter is connected; it does not always mean the battery is charging.

Read with psutil.sensors_battery(), a Python tool for reading operating-system measurements.

Battery used per hour

A percentage point is a change from, for example, 80% to 79%. Losing 6 points in 30 minutes averages 12 points per hour.

We calculate this from battery readings and elapsed time while unplugged. We need at least 10 continuous minutes and a 2-point drop. Charging and recording gaps break the calculation. Rounded battery readings make this an estimate.

Calculated with local Python analysis. This is a rate of battery change, not a measurement of an individual app's power.

Processor use, or CPU

The CPU is the part of your Mac that executes instructions. A core is one unit of that processor. System CPU use describes how busy all your cores were together.

For each process, we compare cumulative processor time between readings. Using 30 seconds of processor time in a 60-second interval means 50% CPU. Several cores working at once can put a process above 100%, or give it more CPU minutes than minutes on the clock.

Busy processors are a clue to battery use. CPU percentage is not battery percentage, and it does not measure graphics or display power.

Read with psutil, using macOS system and process CPU counters. The first reading establishes a starting point; the next reading lets us calculate activity.

Processes and background work

A process is a running program: an app, a helper, or a system task. One app can have several processes. PID means process ID, the number macOS assigns it.

We pair that ID with its start time so a new process cannot inherit an older one's history. Protected processes are skipped. Work that starts and ends between readings may be missed.

Read with psutil.Process. App names are attached only when macOS supplies an identity; we do not guess which app or browser tab owns a helper.

Memory, or RAM

RAM is the working space programs use while they run. The table shows the highest memory use among each process's included activity readings, in megabytes (MB, one million bytes). First readings and incomplete intervals may be excluded. This is different from disk storage.

Using a lot of memory alone does not prove that a process is draining the battery.

Read with psutil.virtual_memory() for the system and Process.memory_info() for processes.

Apps seen in front

The foreground app is the app macOS identifies as active at the moment of a reading. The counts show how often we saw it, not exactly how long you used it. Other apps may still be working in the background.

Read with macOS NSWorkspace.frontmostApplication through PyObjC, which lets Python use Mac APIs.

Readings and recording gaps

A sample is one reading. “Time recorded” is the share of your selected window with continuous observations. Sleep, a stopped collector, and missed readings leave gaps.

A baseline is a comparison period. Here we use the preceding period of the same length. It may contain different work, so a comparison is useful context, not a controlled experiment.

Checked with date-and-time readings and a monotonic clock, which tracks elapsed time, along with the recording interval and session boundaries.

Additional sensors and limits

When available, we also save battery voltage, electrical current, charging state, and cycle count using macOS ioreg and AppleSmartBattery. These are battery-wide readings, not calibrated per-app energy measurements. Cycle count alone is not a battery-health diagnosis.

Disk read/write counters are optional and can be unavailable on macOS. We do not directly measure network traffic, display brightness, GPU activity, or temperature. Missing readings remain unknown.

Reports use local calculations, not an AI model. Possible contributors are ranked by observed CPU work during valid unplugged periods. Correlation means two things happened together; it does not prove that one caused the other.
